## Когда использовать

Продвинутые возможности Git используются при работе в команде, разрешении конфликтов, работе с историей и сложных сценариях разработки.

## Разрешение конфликтов

### Возникновение конфликтов
```bash
# При слиянии веток может возникнуть конфликт
git merge feature/branch

# Git покажет файлы с конфликтами
# <<<<<<< HEAD
# Ваш код
# =======
# Код из другой ветки
# >>>>>>> feature/branch
```

### Разрешение конфликтов
```bash
# 1. Отредактировать файлы с конфликтами вручную
# 2. Добавить разрешенные файлы
git add conflicted_file.py

# 3. Завершить слияние
git commit
```

### Отмена слияния
```bash
# Отменить слияние до коммита
git merge --abort
```

## Rebase

### Базовый rebase
```bash
# Переместить коммиты текущей ветки на вершину другой ветки
git checkout feature/branch
git rebase main

# Интерактивный rebase (последние 3 коммита)
git rebase -i HEAD~3
```

### Интерактивный rebase
```bash
# Редактировать, объединить, удалить коммиты
git rebase -i HEAD~3

# Опции:
# pick - использовать коммит
# reword - изменить сообщение
# edit - редактировать коммит
# squash - объединить с предыдущим
# drop - удалить коммит
```

## Stash (Временное сохранение)

```bash
# Сохранить текущие изменения во временное хранилище
git stash

# Сохранить с описанием
git stash save "Описание"

# Просмотр списка stash
git stash list

# Применить последний stash
git stash apply

# Применить и удалить stash
git stash pop

# Удалить stash
git stash drop stash@{0}
```

## Работа с историей

### Просмотр изменений
```bash
# Изменения в файле
git diff file.py

# Изменения между коммитами
git diff HEAD~1 HEAD

# Изменения в коммите
git show <commit_hash>
```

### Изменение истории
```bash
# Изменить последний коммит
git commit --amend

# Изменить сообщение коммита
git commit --amend -m "Новое сообщение"

# Добавить файлы в последний коммит
git add forgotten_file.py
git commit --amend --no-edit
```

## Cherry-pick

```bash
# Применить конкретный коммит из другой ветки
git cherry-pick <commit_hash>

# Применить несколько коммитов
git cherry-pick <commit1> <commit2>

# Применить диапазон коммитов
git cherry-pick <start_commit>..<end_commit>
```

## Работа с тегами

```bash
# Создать тег
git tag v1.0.0

# Создать тег с сообщением
git tag -a v1.0.0 -m "Версия 1.0.0"

# Просмотр тегов
git tag

# Отправить теги в удаленный репозиторий
git push origin v1.0.0

# Отправить все теги
git push origin --tags
```

## Подмодули (Submodules)

```bash
# Добавить подмодуль
git submodule add <url> path/to/submodule

# Инициализировать подмодули
git submodule init

# Обновить подмодули
git submodule update

# Клонировать репозиторий с подмодулями
git clone --recursive <url>
```

## Хуки (Hooks)

### Pre-commit hook
```bash
# Файл: .git/hooks/pre-commit
#!/bin/bash
# Запуск тестов перед коммитом
pytest
```

### Post-commit hook
```bash
# Файл: .git/hooks/post-commit
#!/bin/bash
# Отправка уведомления после коммита
echo "Коммит создан: $(git log -1 --pretty=format:'%h %s')"
```

## Приоритеты использования

### В первую очередь (по необходимости)
- Разрешение конфликтов при слиянии
- `git stash` для временного сохранения изменений
- `git rebase` для чистой истории

### По необходимости
- Интерактивный rebase для редактирования истории
- Cherry-pick для выборочного применения коммитов
- Работа с тегами для версионирования
- Git hooks для автоматизации

## Примеры использования

### Типичный workflow
```bash
# Создать ветку для новой функции
git checkout -b feature/new-feature

# Работа над функцией
# ... изменения ...

# Сохранить незавершенную работу
git stash

# Переключиться на другую ветку
git checkout main

# Вернуться к работе
git checkout feature/new-feature
git stash pop

# Закоммитить изменения
git add .
git commit -m "Добавлена новая функция"

# Обновить ветку с main
git rebase main

# Отправить изменения
git push origin feature/new-feature
```

- Поддержания чистой истории коммитов
- Работы с несколькими ветками одновременно
- Версионирования релизов через теги
