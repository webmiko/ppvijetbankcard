База знаний (`wiki/База-знаний.md`) имеет **наивысший приоритет** при выборе методов или способов написания кода.

**Принципы:**

- Выбирать методы согласно рекомендациям "Когда использовать"

### 2. Инструкция по разработке
Инструкция (`pre-code/инструкция_разработки.md`) описывает конкретные шаги и подходы к разработке.

**Принципы:**

### 3. Стиль проекта
Если необходимой информации нет в базе знаний или инструкции, действовать на свое усмотрение, но **сохранять подход и стиль написания кода проекта**.

## Стиль кода проекта

### Типизация
- **Обязательно** использовать type hints для всех параметров и возвращаемых значений
- Использовать типы из модуля `typing`: `List`, `Dict`, `Any`, `Optional`, `Union`, `Callable`
- Пример: `def function(param: str) -> List[Dict[str, Any]]:`

### Документация
- **Обязательно** добавлять docstrings ко всем функциям
- Формат: Google style docstrings
- Структура:
  ```python
  """
  Краткое описание функции.

  Args:
      param: Описание параметра

  Returns:
      Описание возвращаемого значения
  """
  ```

### Логирование
- Использовать модуль `logging` через `setup_logger` из `src/logger_config.py`
- Логировать важные операции: начало/конец функций, ошибки, предупреждения
- Уровни: `logger.debug()`, `logger.info()`, `logger.warning()`, `logger.error()`

### Константы
- Выносить все магические числа и строки в именованные константы в начале модуля
- Использовать константы вместо прямых значений
- Примеры констант из проекта:
  - `DEFAULT_BLOCK_SIZE = 4`
  - `MIN_CARD_LENGTH = 13`
  - `MAX_CARD_LENGTH = 19`
  - `ENCODING = "utf-8"`
  - `FILE_READ_MODE = "r"`

### Обработка ошибок
- Явная обработка исключений с логированием
- Возврат понятных значений при ошибках (например, пустой список `[]`)
- Использование `try-except` блоков с конкретными типами исключений

## Важные правила

### ⚠️ НЕ МЕНЯТЬ ОДОБРЕННЫЙ КОД
**Критически важно:** Если код был одобрен ранее, **никогда не менять его самостоятельно** при будущих модернизациях.

**Исключения:**
- Явный запрос пользователя на изменение
- Исправление критических ошибок (с согласованием)
- Рефакторинг по согласованию с пользователем

### Принцип "Явное лучше неявного"
- Использовать именованные константы вместо магических чисел
- Явные параметры вместо неявных значений по умолчанию
- Явные проверки и валидации
- Явные возвращаемые значения и обработка ошибок
