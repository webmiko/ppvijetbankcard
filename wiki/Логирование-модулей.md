# Логирование модулей

## Обзор

Модули `masks` и `utils` используют встроенное логирование для отслеживания своей работы. Логи автоматически записываются в файлы в директории `logs/` при каждом вызове функций этих модулей.

## Автоматическое логирование

Логирование работает автоматически - вам не нужно ничего настраивать. При импорте модулей создаются логгеры, которые записывают информацию о работе функций.

### Модуль masks

Модуль `masks` логирует:
- Начало маскирования номеров карт и счетов (DEBUG)
- Успешное завершение маскирования (INFO)
- Ошибки валидации (ERROR)

```python
from src.masks import get_mask_card_number, get_mask_account

# Автоматически логируется в logs/masks.log
masked_card = get_mask_card_number("1234567890123456")
masked_account = get_mask_account("123456789")
```

### Модуль utils

Модуль `utils` логирует:
- Начало загрузки транзакций (DEBUG)
- Успешную загрузку транзакций (INFO)
- Предупреждения о проблемах (WARNING)
- Ошибки при загрузке (ERROR)

```python
from src.utils import load_transactions_from_json

# Автоматически логируется в logs/utils.log
transactions = load_transactions_from_json("data/operations.json")
```

## Формат логов

Все логи записываются в едином формате:

```
<метка_времени> - <модуль> - <уровень> - <сообщение>
```

### Примеры логов

**Успешные операции:**
```
2025-11-19 00:45:37 - src.masks - INFO - Номер карты успешно замаскирован, длина: 16
2025-11-19 00:45:37 - src.masks - INFO - Номер счёта успешно замаскирован, длина: 16
2025-11-19 00:45:37 - src.utils - INFO - Успешно загружено транзакций: 101 из файла data/operations.json
```

**Ошибки:**
```
2025-11-19 00:45:37 - src.masks - ERROR - Номер карты содержит нецифровые символы: 1234abcd
2025-11-19 00:45:37 - src.masks - ERROR - Некорректная длина номера карты: 5
2025-11-19 00:45:37 - src.utils - ERROR - Ошибка при загрузке файла data/invalid.json: JSONDecodeError - Expecting value: line 1 column 1
```

**Предупреждения:**
```
2025-11-19 00:45:37 - src.utils - WARNING - Файл не найден: nonexistent_file.json
2025-11-19 00:45:37 - src.utils - WARNING - Файл пустой: empty_file.json
2025-11-19 00:45:37 - src.utils - WARNING - Файл содержит не список: data.json, тип: <class 'dict'>
```

**Отладочная информация:**
```
2025-11-19 00:45:37 - src.masks - DEBUG - Начало маскирования номера карты: <class 'str'>
2025-11-19 00:45:37 - src.masks - DEBUG - Длина номера карты: 16
2025-11-19 00:45:37 - src.utils - DEBUG - Начало загрузки транзакций из файла: data/operations.json
```

## Уровни логирования

Проект использует стандартные уровни логирования Python:

- **DEBUG** - детальная информация для отладки (начало функций, промежуточные значения)
- **INFO** - информационные сообщения о нормальной работе (успешное выполнение операций)
- **WARNING** - предупреждения о потенциальных проблемах (файл не найден, но это ожидаемо)
- **ERROR** - ошибки, которые не прерывают выполнение программы (ошибки обработки данных)

## Файлы логов

Логи записываются в отдельные файлы для каждого модуля:

- **logs/masks.log** - логи модуля `masks` (маскирование карт и счетов)
- **logs/utils.log** - логи модуля `utils` (загрузка транзакций)

### Важные особенности

1. **Перезапись при запуске**: Файлы логов перезаписываются при каждом запуске приложения (режим `mode="w"`)

2. **Автоматическое создание**: Директория `logs/` и файлы логов создаются автоматически при первом использовании модулей

3. **Кодировка UTF-8**: Все логи записываются в кодировке UTF-8 для корректной работы с русским текстом

## Просмотр логов

### Командная строка

```bash
# Просмотр всех логов модуля masks
cat logs/masks.log

# Просмотр последних 10 строк логов
tail -n 10 logs/utils.log

# Мониторинг логов в реальном времени
tail -f logs/masks.log

# Поиск ошибок в логах
grep ERROR logs/masks.log
grep ERROR logs/utils.log
```

### Python

```python
# Чтение логов из файла
with open("logs/masks.log", "r", encoding="utf-8") as f:
    logs = f.readlines()
    for line in logs:
        print(line.strip())
```

## Использование в разработке

Логирование помогает при разработке и отладке:

1. **Отслеживание выполнения**: Видно, какие функции вызываются и с какими параметрами
2. **Диагностика ошибок**: Ошибки логируются с подробной информацией
3. **Мониторинг работы**: Можно отслеживать успешные операции и предупреждения

### Пример использования для отладки

```python
from src.masks import get_mask_card_number

# Выполняем операцию
try:
    result = get_mask_card_number("1234567890123456")
    print(f"Результат: {result}")
except ValueError as e:
    print(f"Ошибка: {e}")
    # Проверяем логи для детальной информации
    with open("logs/masks.log", "r", encoding="utf-8") as f:
        print("\nПоследние записи в логе:")
        for line in f.readlines()[-5:]:
            print(line.strip())
```

## Настройка логирования

Логирование настраивается автоматически при импорте модулей. Каждый модуль создает свой логгер с помощью функции `_setup_logger()`.

### Структура настройки

1. Создание логгера с именем модуля
2. Установка уровня логирования (DEBUG)
3. Создание директории `logs/` (если не существует)
4. Настройка FileHandler для записи в файл
5. Настройка форматтера с нужным форматом
6. Добавление handler к логгеру

### Предотвращение дублирования

Логгеры проверяют наличие обработчиков перед добавлением новых, чтобы избежать дублирования записей при повторном импорте модулей.

## Сравнение с декоратором log

В проекте есть два типа логирования:

1. **Логирование модулей** (masks, utils) - автоматическое, встроенное в функции
2. **Декоратор log** (decorators.py) - для логирования любых функций

Декоратор `log` используется для логирования выполнения функций в целом, а логирование модулей предоставляет детальную информацию о работе конкретных функций модулей.

## Тестирование

Логирование проверяется в тестах:

- `tests/test_masks.py` - тесты функций маскировки (логи создаются автоматически)
- `tests/test_utils.py` - тесты функций загрузки (логи создаются автоматически)

При запуске тестов логи также записываются в файлы, что помогает при отладке тестов.
